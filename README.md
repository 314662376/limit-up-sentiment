# 打板情绪看板（双指数）

把 A 股短线打板情绪浓缩成 **两个每分钟更新的数值**，各自配 1 日 / 5 日分时图。

| 指数 | 含义 | 单位 | y 轴（固定） |
|---|---|---|---|
| ① 涨停情绪指数 | 打板赚钱效应的强弱 | 无量纲，1.000 = 中性 | `0.925 ~ 1.075`（0.025 一档） |
| ② 打板收益 | 昨日涨停 / 炸板组合今日的期望盈亏 | 元 / 万元本金，0 = 不赚不亏 | `-200 ~ 300`（100 一档） |

```
① 值 = 昨日封板率/100 × (883900涨跌幅% ÷ 100) + 1 + 上证涨跌幅% ÷ 20
      Excel: =C3/100*D3+1+E3/20

② 值 = 10000×(1+883918涨跌幅%)×昨日炸板率 + 10000×(1+883900涨跌幅%)×昨日非一字板封板率 − 10000
      Excel: =10000*(1+F2)*E2+10000*(1+D2)*C2-10000
```

> ②中的「昨日非一字板封板率」与「昨日炸板率」**恒相加为 100%**（互为补数），
> 因此可化简为 `② = 100 × ( 883918% × 炸板率 + 883900% × 非一字板封板率 )`。
> 用截图那行的数验算：`10000×1.0035×0.5208 + 10000×1.0316×0.4792 − 10000 = 169.6552` ✔ 与 Excel 一致。
>
> ② 的经济含义：**每 1 万元本金，按昨日「非一字板涨停 : 炸板」的家数比例平铺一篮子，
> 持有到今天的期望盈亏**。指数②的权重是「家数比」，指数①的权重是「上证/20」，两者不能互相替代。

**① 高于 1.000 表示情绪偏强，低于 1.000 偏弱；② 高于 0 表示打板整体赚钱。**

## 视图切换

两张图共用顶部「视角」切换按钮（`1日` / `5日`），也可用 `?view=5d` 深链接直达。

| 视图 | 内容 | 横轴 |
|---|---|---|
| **1日**（默认） | 当日实时曲线，每分钟刷新 | 固定为完整交易日 `09:30–11:30` + `13:00–15:00`（242 刻度，午休不占位），盘中只铺到当前时刻，**不随时间向右延长** |
| **5日** | 最近 5 个交易日叠加对比，每条线的基准取各自的前一交易日 | 由各日数据并集决定 |

切换是纯前端重绘（数据已在内存里），不重新请求接口。

### 1日视图的 y 轴固定，不随数据缩放

- ① 固定 `0.925 ~ 1.075`，灰色虚线为 `1.000` 中性基准；
- ② 固定 `-200 ~ 300`，灰色虚线为 `0`。
- 超出区间的点会被**裁掉不可见**，图下方给出「⚠ 有 N 个点超出固定显示区间」提示，避免误读成"没数据"。

### 阈值警示（红 / 绿）

| 图 | 下阈（标红） | 上阈（标绿） |
|---|---|---|
| ① 涨停情绪指数 | `0.95` | `1.05` |
| ② 打板收益 | `-100` | `200` |

- **1 日图**：用 `visualMap` 把线段按 y 值**分段染色**——跌破下阈的段变红、涨破上阈的段变绿，区间内保持本色（①蓝 / ②橙）。

- 虚线标签放在**右端**（`insideEndTop`），否则会与左端 y 轴刻度标签压在一起。

## 取数口径

| 输入 | 定义 | 来源 |
|---|---|---|
| 涨停池家数 | 当日最终封住涨停的家数 | 同花顺 `dataapi/limit_up/limit_up_pool` |
| 炸板池家数 | 当日曾涨停但收盘未封住的家数 | 同花顺 `dataapi/limit_up/open_limit_pool` |
| **一字板家数** | 涨停池中 `limit_up_type == "一字板"` 的家数 | 同上（需带完整 `field` 列表才会返回该字段） |
| 883900 | 同花顺「昨日涨停表现」当日实时涨跌幅 | `d.10jqka.com.cn` 公开行情（`48_883900`） |
| 883918 | 同花顺「昨日炸板股」当日实时涨跌幅 | `d.10jqka.com.cn` 公开行情（`48_883918`） |
| 上证指数 | 上证指数当日实时涨跌幅 | `d.10jqka.com.cn`（`hs_1A0001`） |

两个封板率的算法**分母不同**，别混用：

```
总封板率       = 涨停家数 ÷ (涨停家数 + 炸板家数)                      ← 指数①用
非一字板封板率 = 非一字板涨停家数 ÷ (非一字板涨停家数 + 炸板家数)      ← 指数②用
非一字板涨停家数 = 涨停家数 − 一字板家数
炸板率         = 炸板家数 ÷ (非一字板涨停家数 + 炸板家数) = 100% − 非一字板封板率
```

为什么指数②要剔除一字板：**一字板开盘即封死、根本买不进**，把它算进"打板成功"会高估收益率。
指数①沿用总数口径（与你原来的 Excel 一致），两者并存、互不覆盖。

全部为同花顺**公开**行情接口，无需密钥。

## 数据是怎么记录下来的

静态页面不能写文件，所以历史数据由 **GitHub Actions** 采集，**每个交易日收盘后跑一次**：

```
.github/workflows/collect.yml
  └─ 交易日 15:10 / 15:40 / 16:10 (UTC 07:10 / 07:40 / 08:10) 各触发一次
        ↓  node scripts/collect.js --full
     一次抓取当日「完整分时」（241 个点），一次写齐 —— 同日重跑幂等
data/YYYY-MM-DD.json   ← 当日全部分钟点：{t, v(①), v2(②), a(883900), b(上证), c(883918)}
                          + rate（含 zt/zb/oneWord/base/rate/fbl/zbl）
data/latest.json       ← 当前生效的基准，供前端兜底读取
data/index.json        ← 已收录的交易日列表
```

> **为什么不是盘中逐分钟轮询？** 同花顺 `v6/time` 分时接口在**盘后仍返回当日完整的 241 个点**，
> 所以只要收盘后成功跑一次，全天数据就齐了。这比「9 轮 × 14 分钟轮询」可靠得多 ——
> 实测那版 **cron 一次都没触发**（GitHub 的 scheduled workflow 对新仓库 / 低活跃仓库会丢调度），
> 结果当天只存到 11:26 的半天数据，盘后页面就按这半天算，显示出了一个离谱的值。
> 现在改成「一次抓全天」，并给了 3 个冗余触发时间。

页面读取逻辑：

- **任何时段都直连**同花顺分时接口（883900 / 883918 / 上证三条）现算。
  盘后该接口返回的是当日完整分时、末点即收盘值，所以**收盘后显示的也是收盘结果**，不再依赖存档。
- 直连失败时，才回落到 `data/` 里最近一个交易日的存档（此时状态栏会标 `[分时取数失败，暂用存档]`）。
- 「昨日封板率」基准同样是**页面直连** `data.10jqka.com.cn` 的涨停池 / 炸板池现算，
  按数据日期缓存（日频常量，不会每分钟重复请求）；取不到才回落到存档（状态栏标 `［存档］`）。

> 关于 `data.10jqka.com.cn` 的 CORS：之前记的「响应头依赖 Referer、浏览器不能直连」**是错的**。
> 实测该接口会把请求的 `Origin` 原样回显到 `Access-Control-Allow-Origin`，浏览器**可以**跨域直连。
> 请求带 8 秒超时（某些网络会挂住不报错），失败后退避 10 分钟并走存档兜底。

### ⚠️ 关于 5 日图：无法回填，只能逐日累积

同花顺 `v6/time/{prefix}_{code}/{YYYYMMDD}.js` **不支持按日期取历史分时**——路径里的日期会被忽略，
盘中访问返回当日实时数据、非交易时段返回最近一个完整交易日。

> 这个坑曾经真实踩过：早期用 `backfill.js --days=5` "回填成功"的 5 个交易日，
> 解出来是**同一份数据复制了 5 份**（比对 `b`（上证涨跌幅）序列完全一致）。
> 现已在 `getTimeSeries()` 里加了 `pack.date === 请求日期` 的硬校验，不符直接抛错跳过。

因此：

- **① 的 5 日图**只需 `883900 + 上证`，已有存档即可回溯；
- **② 的 5 日图**还需要 `883918` 分时，**无法回溯**，只能从本指标上线当天起逐日累积，
  页面对此会给出「打板收益的历史曲线积累中」提示。

## 本地运行

```bash
python -m http.server 8898       # 然后打开 http://127.0.0.1:8898/
```

验证接口连通性（只读不写，会逐条打印 5 个数据源是否可用）：

```bash
node scripts/collect.js --probe
```

**抓当日完整分时写盘（推荐，收盘后跑一次即可补齐全天）**：

```bash
node scripts/collect.js --full
```

手动采一次：

```bash
node scripts/collect.js --once
```

```bash
git init && git add . && git commit -m "feat: 打板情绪看板"
```

## 口径核对记录（2026-10-09）

拿用户 Excel 的两行数据做过逐项核对：

| 行 | Excel ② | Excel 的 883900 | Excel 的 883918 | Excel 的 非一字板封板率 |
|---|---|---|---|---|
| 1008 | −92.3306 | 0.13% | −4.76% | 78.46% |
| 1009 | 181.25 | **3.08%** | **0.48%** | **51.25%** |

结论：

1. **公式完全一致**，两条 Excel 行都能被本页公式精确复现（`181.25 = 10000×1.0048×0.4875 + 10000×1.0308×0.5125 − 10000` ✔）。
2. **883900 对得上**：10-08 收 +0.128%、10-09 收 +3.084%（同花顺日线 / iFinD 双向确认）。
3. **Excel 里 10-09 的 883918「0.48%」是取到了盘中值，不是收盘值**。
   883918 在 10-09 的正式收盘涨跌幅是 **+0.786%**（收盘 458.026 / 昨收 454.454），
   同花顺 `realhead`、`v6/time` 末点、iFinD `883918.TI` 三处一致；
   0.48% 只出现在 14:12–14:31 这一段，属于典型的"表格没刷新到收盘"。
   按 0.48% 算出的 181.25 因此会**低估约 15**。
4. **Excel 的「非一字板封板率」不是同花顺池子口径**。
   同花顺 `dataapi` 的 10-08 是 涨停 42（含一字板 3）/ 炸板 32 → 非一字板封板率 **54.93%**；
   东财是 43 / 32 → 57.33%；把近 26 个交易日 × 各种子集（剔 ST、剔新股、剔 T 字板、仅主板、含北交所…）
   全扫了一遍，**没有任何一天、任何口径能凑出 51.25% / 48.75%**（= 41/80）或 78.46% / 21.54%（= 51/65）。
   所以这一列应来自另一个数据源，需要用户确认后才能在页面里对齐。

**同口径下，10-09 收盘值为 204.83**（① = 1.0200）。

## 已知限制

- GitHub Actions 的定时触发**不保证准点**，高峰期可能延迟；本工作流已给 3 个冗余时间点，
  且改成「一次抓全天」，漏 1–2 次也不影响数据完整性。
- `883918` 的**日线历史数据是同花顺侧的脏数据**（长期恒等于 1000.008），只有实时 / 分时可用。
- ② 的 y 轴固定在 `-200 ~ 300`（原为 `-100 ~ 200`，10-09 收盘 204.83 顶出上界后放宽）。
  超出 `300` / 低于 `-200` 的点仍会被裁掉（图下有提示）。
- 同花顺接口如变更路径或加反爬，采集会失败，页面会退回显示最近存档（不会白屏）。
- 页面与采集脚本都依赖同花顺公开接口，属第三方数据，**不保证长期稳定**。
